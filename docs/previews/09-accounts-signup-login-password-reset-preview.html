Overload · Accounts: Signup, Login & Password Reset

UI preview — sign in, invited signup, password recovery, settings, and account deletion, both appearance modes

Sign inSignupRecoverySettingsDeleteTheme
Appearance
Design handoff · v1.1

The door is plain, the lock is on the server, and the only exit that destroys history asks for your password.

Invited signup, sign in and out, password recovery by email, name and timezone in Settings, and permanent account deletion. No tour, greeting, appearance setting, or admin surface ships here. Check every frame against one commitment: nothing on these screens tells anyone whether an address has an account, except signup after a valid invite code. Use the Light / Dark switch to flip every product surface.

Note This preview is a rendering of the design, not product code. The app is built with Tailwind and shadcn/ui against the theme in globals.css; nothing here is copied into it. Mock data only. The brand mark is the app's own public/brand/overload-mark.png.

What these screens are built to respect

The design commitments a reviewer should check the frames above against.

Privacy and membership

  • One recovery answer. “Check your email” reads the same for a known and an unknown address (§03, side by side).
  • One login failure. “Wrong email or password.” covers unknown email and wrong password alike.
  • The code gates the email. A wrong invite code is the only error shown; “already exists” appears only after a valid code.
  • No one else, ever. The only email shown is the signed-in account's own or the one just typed. No other name or address appears anywhere.
  • Signup is closed by default. With no invite code configured, /signup shows “Signup isn't open”.

Quiet doors, deliberate exit

  • Doors, not a lobby. Wordmark, one card, one primary action, at most two links. No tour, welcome, or marketing copy; a new account lands on Today's existing empty state.
  • Routine above, irreversible apart. Save sits at thumb reach; Delete account sits below a divider and opens its own page.
  • Delete is counted and password-confirmed. The inventory uses the lifter's own numbers; the library is untouched; failures say exactly what did and didn't happen.
  • Timezone is plain. The IANA name, one line saying Today follows it, and a device hint that never changes anything without Save.
  • Theme only. No progress or deload color, no appearance control (Personalization owns it), shadows only on the menu and toasts.
